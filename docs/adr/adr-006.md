# ADR-006: Adopt Builder Pattern for PlaySessions and Reject Global Singletons

**Date:** 2026-11-02 | **Status:** Accepted

## Context

Constructing a `PlaySession` requires core identity and timing fields (`game_id`, `date`, `duration_seconds`), optional metadata (`subject`, `notes`, `id`), and the coupled invariant `duration_hours = duration_seconds / 3600.0`. Multi-argument instantiation and hour conversion were duplicated across `SessionService` and deferred review submission in `presentation/gui.py`, while introducing global Singletons for repositories or stores would hide dependencies and break test isolation.

## Decision

We will implement `PlaySessionBuilder` in `domain/session.py` to assemble and validate `PlaySession` instances step by step and centralize the `duration_hours` derivation inside `build()`. Conversely, we deliberately reject the Singleton pattern across the Data and Service tiers, continuing to instantiate repositories and `UiSettingsStore` once at startup and pass them via constructor injection.

## Consequences

Callers construct `PlaySession` objects fluently without duplicating unit-conversion math or positional arguments, and domain validation rules live in one testable class. Rejecting Singletons keeps all service and UI dependencies explicit and trivial to swap with test doubles in `pytest`, at the cost of passing dependencies explicitly from `main.py`.
