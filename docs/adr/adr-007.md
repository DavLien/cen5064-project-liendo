# ADR-007: Scope Library Games by Platform and Drive Status via Lifecycle Events

**Date:** 2026-10-30 | **Status:** Accepted

## Context

Players often own or play the same game across multiple platforms (for example, PC and PlayStation 5), and tracking separate playthroughs requires independent session logs and completion statuses per version. Additionally, letting users manually pick any status from a free-form dropdown could create inconsistent states, such as a game marked `In Progress` with zero recorded sessions or `Backlog` with completed reviews.

## Decision

We will uniquely identify library entries by the composite pair `(title, platform)` in `CatalogService` and `SqliteGameRepository` rather than by `catalog_id` alone. Furthermore, library statuses (`Backlog`, `In Progress`, `Completed`, `Abandoned`) will be driven automatically by domain events in `SessionService` and `ReviewService`—promoting `Backlog` to `In Progress` when the first session is logged, setting `Completed` or `Abandoned` upon review submission, and reverting status when priority sessions or reviews are deleted.

## Consequences

Users can track separate playthroughs and playtimes for the same title on different platforms, and library categories always stay consistent with underlying session and review records. However, every deletion path in `SessionService` and `Presentation` must evaluate remaining sessions and milestone reviews to keep the derived status synchronized.
