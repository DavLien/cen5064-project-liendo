# ADR-002: Building the Presentation Tier (GUI) using CustomTkinter

**Date:** 2026-10-11
**Status:** Accepted

## Context

The midterm deliverable requires a first working slice with a functional UI that travels end-to-end to the data store. GameLedger is intended
to be a persistent, locally installed personal desktop video game tool rather than a distributed service. Implementing a standard web-based
frontend (e.g., Flask or FastAPI with HTML/CSS) would require running a local web server and splitting development focus across multiple languages,
introducing unnecessary friction and risking the single-semester deadline.

## Decision

I will build the Presentation tier as a native desktop GUI using the CustomTkinter Python library. The UI will act as a thick client that directly
instantiates the Service tier orchestrators (e.g., `CatalogService`), keeping the entire 4-tier architecture unified in pure Python without needing
a local web server.

## Consequences

This accelerates development by eliminating context-switching between Python and web frontend languages, securing the midterm working slice. It also
guarantees reviewers can run the application seamlessly via a single `python main.py` or `py main.py` execution without managing server ports. However,
it tightly couples the UI to desktop operating systems, deliberately ruling out a mobile or cloud-hosted web version.
