# ADR-005: Isolate UI Settings Persistence into UiSettingsStore (SRP)

**Date:** 2026-11-25 | **Status:** Accepted

## Context

`GameLedgerApp` in `presentation/gui.py` originally handled both Tkinter/CustomTkinter UI layout management and direct JSON file I/O for persisting the user's resizable sidebar width (`data/ui_settings.json`). Mixing presentation rendering with disk persistence violated the Single Responsibility Principle (SRP) and made settings error-handling untestable without instantiating a GUI window.

## Decision

We will extract all UI preference persistence into a dedicated `UiSettingsStore` class (`data/ui_settings_store.py`) that encapsulates file paths, minimum-width clamping, and malformed-JSON recovery, and exclude `data/ui_settings.json` from Git tracking via `.gitignore`. `GameLedgerApp` will delegate loading and saving sidebar dimensions to `UiSettingsStore`.

## Consequences

`GameLedgerApp` and `UiSettingsStore` each have a single reason to change, and settings round-trips and corrupt-file fallbacks are covered by isolated `pytest` unit tests without launching Tkinter. This adds a small persistence module to the Data tier, while keeping local user layout preferences out of version control.
