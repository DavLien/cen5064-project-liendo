# ADR-008: Defer Session Persistence Across Multi-Step Completion and Abandonment Flows

**Date:** 2026-11-06 | **Status:** Accepted

## Context

When finishing a stopwatch run on the Session Submission screen, users can toggle `Completed` (`✓`) or `Abandoned` (`X`) to transition directly into the Rating & Review screen before saving. Writing the play session to SQLite immediately upon leaving the submission screen would leave behind orphaned session records and altered game statuses if the user later clicks `Cancel` on the review screen.

## Decision

When a user submits a stopwatch session with a completion or abandonment toggle active, `presentation/gui.py` will construct an in-memory `PlaySession` flagged with `is_deferred_new` via `PlaySessionBuilder` and pass it to `build_review_screen`. Both the new play session and the `GameReview` record are persisted together only when the user confirms `Post` or `Skip`.

## Consequences

Canceling out of the review step leaves the SQLite database and game status completely untouched, preventing partial writes across multi-screen workflows. This requires `ReviewService` and `build_review_screen` to accept an optional `pending_session` parameter and branch between inserting a new session or updating an edited one.
